# WHA Magic Compiler: Symbol Semantics Catalog

> **Unofficial fan-project notice:** This planning spec is for an unofficial Witch Hat Atelier fan project. It is not affiliated with, sponsored by, or endorsed by Kamome Shirahama, Kodansha, or any Witch Hat Atelier rights holder.

This catalog is the source of truth for WHA symbol registry IDs used by future import, semantic analysis, diagnostics, assets, render planning, and effect graph generation. It is conservative and now scoped to the Telepedia `Signs Explained` **Officially named** section for signs, plus exactly two custom/project-supported unofficial sign exceptions: Crosshair and Radial. Known artwork may render, but only officially named signs or those two explicitly supported unofficial signs may produce active simulator effects. Other sign names from the page's `Unofficially Named` section, custom labels, and unofficial spell inferences are ignored for active behavior in this project. For long-term backlog review, Billow, Orb, and Repetition are the only deferred-interest symbols; all other disabled/deferred labels are ultra-deferred unless a later explicit project decision promotes them.

## Feature-local acceptance checklist

This artifact fulfills `VAL-SYMBOL-001` through `VAL-SYMBOL-011`.

- [x] Every required shape, sigil, sign, and toh has a catalog row.
- [x] Every row includes category, WHA display name, stable registry ID, canonical meaning, simulator effect, confidence tier, evidence/source notes, geometry modifiers, invalid-use cases, diagnostics/warnings, and implementation status.
- [x] Related symbols and homonyms are separated or explicitly aliased.
- [x] Decorative, creature, ambiguous, unsupported, custom, unresolved, and forbidden/body-affecting symbols safely reject or render visual-only.
- [x] Each sign declares geometry applicability.
- [x] Every symbol maps to effect capability or a safe rejection.

## Shared registry and evidence rules

Registry IDs are stable semantic identities, not asset paths. Future WHA fan assets and alternate/open assets must attach to these IDs through swappable asset packs; filenames, image hashes, and custom images cannot create active semantics.

Each catalog row is a symbol entry. Its `category` field is carried twice for reviewability: by the section/table it appears in (`Shape`, `Sigil`, `Sign`, or `Toh`) and by its stable registry ID prefix (`shape.`, `sigil.`, `sign.`, or `toh.`). The remaining columns provide WHA display name, canonical meaning, simulator effect, confidence tier, evidence/source notes, geometry modifiers or applicability, invalid-use cases, diagnostics/warnings, and implementation status.

| Field convention | Rule |
|---|---|
| Shapes | `shape.<name>` |
| Sigils | `sigil.<name>` |
| Signs | `sign.<name>` |
| Tohs | `toh.<name>` |
| Custom imported images | `import.visual.<stableImportId>` until manually resolved to a known registry ID |
| Unresolved imported IDs | Preserve source ID in diagnostics; do not mint active semantic IDs |

Confidence tiers match `spec/magic-engine.md`: `canon_explicit`, `canon_observed`, `canon_strong_inference`, `fan_documented_plausible`, and `speculative_disabled`. `custom_project_supported` may also appear as a project authority marker for the explicit Crosshair/Radial exceptions; it is not a canon confidence claim and must remain labeled as custom-supported in diagnostics and effect graph provenance.

Evidence shorthand:

- `STD-EVIDENCE`: `spec/magic-engine.md`, evidence standard and promotion thresholds.
- `DOSSIER:*`: spell dossier entries in `spec/magic-engine.md`.
- `SRC-SIGILS`: Witch Hat Atelier Wiki, “Sigils Explained”, secondary/fan-documented.
- `SRC-SIGNS`: Witch Hat Atelier Wiki, “Signs Explained”, secondary reference. For this project, signs under its `Officially named` heading are accepted as named sign registry authority; Crosshair and Radial are accepted as explicitly custom/project-supported unofficial exceptions. Other entries under `Unofficially Named` are cataloged only as ignored/out-of-scope visual or diagnostic labels.
- `SRC-MAGIC`: Witch Hat Atelier Wiki, “Magic”, secondary/fan-documented.
- `NO_ACTIVE_EVIDENCE`: no gathered canon-backed behavior sufficient for an active primitive.

## Diagnostic vocabulary used by the catalog

| Diagnostic code | Status | Representative trigger | Conservative fallback |
|---|---|---|---|
| `visual_only_symbol` | `visual_only` | Decorative creature sigil, shape-only ornament, custom image, or toh with no active evidence. | Render if an asset exists; omit effect graph nodes. |
| `ambiguous_symbol_semantics` | `ambiguous_semantics` | Known WHA mark with conflicting or incomplete meaning. | Preserve identity/provenance; no active effect unless selected as a narrow template. |
| `unsupported_symbol` | `unsupported_symbol` | Unknown registry ID or symbol outside this catalog. | Preserve import ID for rendering/diagnostics; no active effect. |
| `speculative_symbol_behavior` | `speculative_disabled` | Physics/game-like behavior not evidenced in WHA sources. | Diagnostic only. |
| `invalid_symbol_pairing` | `nonsensical_combination` | Sign has no applicable domain, shape field, source mode, or line/ring context. | No active effect; explain missing domain/context. |
| `invalid_structure_for_symbol` | `invalid_structure` | Required ring, placement, connection, or boundary ownership is absent. | No active effect for affected symbol. |
| `unstable_geometry` | `unstable_structure` | Supported sign is skewed, imbalanced, or near-boundary beyond evidenced scope. | Compile with warning or downgrade to visual-only. |
| `conflicting_symbol_effects` | `conflicting_effects` | Same target receives contradictory active signs without precedence. | Block affected effect nodes. |
| `forbidden_body_affecting_symbol` | `forbidden_or_body_affecting` | Puppet/body-control/living-target use. | Block active behavior; render mark only if safe. |
| `deprecated_or_variant_symbol` | `compiled_with_warnings` | Retconned or variant usage such as deprecated float-based Pyreball construction. | Prefer corrected registry/template; keep provenance warning. |

## Sign catalog and geometry applicability matrix

Signs express forces, shapes, source modes, constraints, targeting, or modifiers only when paired with an applicable domain/sigil, ring structure, and evidence. Geometry fields not listed for a sign are preserved for rendering/provenance but cannot alter active semantics.


### Official named sign scope from `SRC-SIGNS`

The `Signs Explained` page separates sign names into `Officially named` and `Unofficially Named`. For this project, the officially named signs are: Column, Dispersion, Levitation, Pull, Crush, Float, Region, Convergence, Collection, Billow, Repetition, Weave, Cool, Strengthen, Sights Set, Entwine, Sign of Wind, Aeriforms Defined, Gather, and Glaives. These names may be resolved to stable `sign.*` IDs, while active behavior still requires evidence-tier and template checks. Crosshair and Radial are not official names, but are explicit custom/project-supported exceptions for the first implementation and must keep custom-supported provenance.

The following current catalog labels are not official sign names for project behavior and MUST be ignored/out-of-scope for active semantics unless a later official source or explicit project decision promotes them: Diamond, Window, Enlarge, Bolt, Eye, Vision, Bend, Rain, Puppet, Bind, Orb, Purify, Link, and Stability. Importers may preserve them as renderable/diagnostic identities, but they cannot guide compiler rules, fixtures, or effect graph nodes. Orb is nevertheless kept in the deferred-interest backlog because the project owner may want to revisit it late-game; the rest of this ignored group is ultra-deferred.

### Official signs synthesis (M6 compiler contract)

These rules document the implemented official-sign compiler behavior (`VAL-SPEC-001`). Verification uses **sign-first** synthetic fixtures across multiple domain sigils (water, fire, wind, earth, light); dossier spell clones are hints only, not per-spell compiler gates. Directional official signs reuse **column-parity geometry** (radial placement, `angle`-based facing/inversion, duplicate vector summation, symmetry classes). Locked custom signs (`sign.radial`, `sign.crosshair`) are unchanged for current regression fixtures; contextual Crosshair modes are planned targeting semantics that must be introduced without silently breaking those fixtures.

**Deferred catalog (M5):** `sign.float` is deprecated (`REJECT_FLOAT_DETACHED_OUTPUT`); prefer `sign.levitation`. Deferred-interest backlog is limited to Billow, Orb, and Repetition (`sign.repetition` / `sigil.repetition`) for late-game review. Weave, Entwine, Sign of Wind, Aeriforms Defined, Glaives, Sights Set, Float, Strengthen expansion, and the remaining ignored/out-of-scope labels are ultra-deferred: diagnostic/import identity only, no active effect nodes unless a later explicit project decision promotes them. **`sign.repetition` and `sigil.repetition` are out of scope** for official-signs synthesis (no active repetition rules). Patterns and diagnostics codes are exercised in `test/official-signs-m5-catalog.test.js` (`VAL-FLOAT-001`, `VAL-CATALOG-001`).

## Implementation status policy

- `Active in narrow templates` means future compiler code may create effect graph nodes only when the exact symbol combination, source mode, geometry, and evidence-linked template preconditions match.
- `Deferred-interest` means keep the symbol visible in late-game backlog reviews even though it has no active behavior now.
- `Ultra-deferred` means keep import/diagnostic identity only and do not surface it as near-term work unless the project owner explicitly promotes it.
- `Warning/disabled` means the symbol identity is known but active effect generation is withheld.
- `Disabled` means no active semantics are currently permitted.
- `Blocked` means the category is safety-sensitive or body-affecting and must fail closed even if artwork renders.
- All statuses preserve stable registry IDs for diagnostics, import provenance, asset lookup, and future review.
